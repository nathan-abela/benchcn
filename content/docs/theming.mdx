benchcn components follow your project's shadcn theme. Any base colour and accent works. This site happens to use zinc.

## 1. Chrome follows your theme

Cards, bezels, text, borders and focus rings read the standard shadcn variables: `--background`, `--card`, `--muted`, `--border`, `--primary`, `--ring`. Nothing to configure.

## 2. Channels have their own tokens

Scope channels, analyzer lanes, bitfield fields and timing diagram buses use `--channel-1` to `--channel-4`, which `@benchcn/tokens` adds at one perceived lightness per theme, so no channel outweighs another. The scope, analyzer and serial console screens carry the `dark` class, so their traces take the dark values in both themes. A channel without its own token falls back to your `--chart-1` to `--chart-5`, so a fifth lane, or a project that removes the channel tokens, follows your chart palette.

## 3. Physical colours are props

LEDs, LCD backlights and seven-segment digits have fixed colours in the real world, so they take a `color` prop with presets (`red`, `amber`, `green`, `blue`, `white`) and default to `--primary`.

## Status tokens

shadcn ships `--destructive` but no success or warning token. The `@benchcn/tokens` item adds them and every benchcn component depends on it:

```css
:root {
  --success: oklch(52.7% 0.154 150.069);
  --success-foreground: oklch(98.2% 0.018 155.826);
  --warning: oklch(0.555 0.132 58);
  --warning-foreground: oklch(98.7% 0.022 95.277);
}
```

They are mapped into Tailwind as `bg-success`, `text-warning` and so on. Components use them as text as well as fills, so the light values are dark enough to keep 4.5:1 on white, with warning turned toward yellow to stay apart from red. The dark values are brighter and pass on dark cards.

## Reduced motion

Every animation respects `prefers-reduced-motion`. Phosphor persistence, spring toggles and press-and-hold fills fall back to instant state changes.
