## Usage

Lanes are arrays of logic levels at a known sample rate. Decoding is opt-in and names the lanes by id.

```tsx
import { LogicAnalyzer } from "@/components/ui/logic-analyzer";

<LogicAnalyzer
  lanes={[
    { id: "scl", label: "SCL", data: scl, sampleRate: 1_000_000 },
    { id: "sda", label: "SDA", data: sda, sampleRate: 1_000_000 },
  ]}
  decode={{ protocol: "i2c", sda: "sda", scl: "scl" }}
/>;
```

The decoder is a plain function you can use without the component, for tests or for a text log:

```ts
import { decodeI2c, summarizeI2c } from "@/lib/decoders/i2c";

const frames = decodeI2c({ sda, scl, sampleRate: 1_000_000 });
console.log(summarizeI2c(frames));
// W 0x76: F7
// R 0x76: A0 00 87 FB F7 47 9C B8
```

## Protocols

`decode` names the protocol and the lanes it reads. Frames are drawn above the lane that carries the data.

```tsx
// Drawn above SDA.
decode={{ protocol: "i2c", sda: "sda", scl: "scl" }}

// Drawn above MOSI. `miso` and `cs` are optional; mode, bit order and word size default to 0, MSB first and 8.
decode={{ protocol: "spi", sclk: "sclk", mosi: "mosi", miso: "miso", cs: "cs", mode: 0 }}

// Drawn above the serial line. 8N1 unless you say otherwise.
decode={{ protocol: "uart", rx: "rx", baudRate: 115_200 }}

// Modbus RTU on the same serial line. 8E1 unless you set `parity`; no parity means two stop bits.
decode={{ protocol: "modbus", rx: "rx", baudRate: 19_200 }}
```

The list groups frames the way each bus does: one row per I²C start, per SPI chip select, per line of UART text (a line feed or an idle gap ends the row), and per Modbus frame.

Modbus frames end after 3.5 characters of silence, a gap over 1.5 characters inside one is flagged, and every CRC is checked. Function codes 01 to 06, 15 and 16 are parsed, and others show their bytes in hex.

## Examples

### Open on the first transaction

A whole capture at 100 kHz is too dense to read: SCL becomes a solid band and every byte an ellipsis. `defaultWindow="first"` opens on the first decoded transaction instead, and returns there whenever `lanes` change. `Fit` still shows the whole capture.

```tsx
<LogicAnalyzer lanes={lanes} decode={decode} defaultWindow="first" />
```

### Controlled window

Share one time window between two analyzers, or drive it from a timeline elsewhere on the page.

```tsx
const [window, setWindow] = useState({ start: 0, end: 0.004 });

<LogicAnalyzer lanes={lanes} window={window} onWindowChange={setWindow} />;
```

### Lanes only

Leave `decode` out for plain digital capture, for example a PWM line next to its enable pin.

### Without the list

`list={false}` keeps the lanes and the overlay but drops the transaction table, for tight dashboards.

## Decoded frames

| Protocol | Frame                 | Drawn as                                                       |
| -------- | --------------------- | -------------------------------------------------------------- |
| I²C      | Start, repeated start | Green dot labelled S                                           |
| I²C      | Address               | Bubble with the 7-bit address and R or W                       |
| I²C      | Data                  | Bubble with the byte in hex                                    |
| I²C      | NACK                  | ✕ after the byte                                               |
| I²C      | Stop                  | Red dot labelled P                                             |
| SPI      | Select, deselect      | Green dot, red dot                                             |
| SPI      | Word                  | Bubble with MOSI in hex, then MISO when it is not zero         |
| UART     | Byte                  | Bubble with the character, or the byte in hex if not printable |
| UART     | Framing, parity error | Red bubble naming the error                                    |
| Modbus   | Address, function     | Bubbles in the address colour, red for an exception            |
| Modbus   | Data                  | Bubble with the byte in hex                                    |
| Modbus   | CRC                   | One bubble over both bytes, red when it does not match         |
| Modbus   | Gap over 1.5 chars    | Red bubble over the silence                                    |

## Theming

Lanes use `--channel-1` to `--channel-4` from `@benchcn/tokens` (then `--chart-n`, then `color`). Start and stop markers use `--success` and `--destructive`, and UART and Modbus errors use `--destructive`, in the lanes and in the list. The screen is always dark.

## Accessibility

The lanes are drawn on a canvas and marked decorative. The decoded transactions are real text: a visually hidden summary next to the canvas and the clickable list under it. Zoom in, zoom out and fit are buttons in the header, so keyboard users have the same control as the wheel.
